Карпов Андрей Сергеевич, ИНБО-20-23. Вариант 9 — частичный индекс незавершённых заказов.

## Запрос и индексы

Выбраны отменённые заказы за январь 2018 года: `order_status = 'canceled'` и полуинтервал времени `[2018-01-01, 2018-02-01)`. Запрос возвращает 34 строки из 99 441 (0,034 %).

Первый индекс `idx_lab13_status_date` — составной B-tree по `(order_status, order_purchase_timestamp)`: сначала равенство статуса, затем диапазон времени. PK-индекс не изменяется. В исходной таблице ранее созданных учебных вторичных индексов не было; SQL показывает исходный список индексов и удаляет только индексы этого опыта.

Второй индекс `idx_lab13_unfinished` имеет те же ключи и предикат `order_status <> 'delivered'`. Условие `order_status = 'canceled'` гарантирует попадание в частичный индекс. Он хранит только 2 963 заказа вместо всех 99 441.

## Сравнение планов

PostgreSQL 17.5; реальные CSV Olist. После создания каждого индекса выполнен ANALYZE. В таблице `actual total` — конечное время корневого узла; `Execution` — время выполнения всего запроса. Shared hit/read — счётчики корневого узла, без суммирования вложенных узлов.

| Вариант | Scan | actual total, мс | Execution, мс | Rows | Shared hit/read |
|---|---|---:|---:|---:|---|
| До индекса | Seq Scan | 3.383 | 3.388 | 34 | 1840 / 0 |
| Составной индекс | Index Scan | 0.029 | 0.035 | 34 | 34 / 3 |
| Частичный индекс | Index Scan | 0.027 | 0.031 | 34 | 34 / 2 |
| Массовый предикат | Seq Scan | 5.202 | 6.880 | 96478 | 1840 / 0 |

| Индекс | Размер, байт | Размер PostgreSQL |
|---|---:|---|
| Составной | 4038656 | 3944 kB |
| Частичный | 131072 | 128 kB |

Для 34 строк использованы соответственно `idx_lab13_status_date` и `idx_lab13_unfinished`. В исходном плане `Seq Scan` отфильтровал 99 407 строк и обратился к 1 840 буферам. С индексами число обращений уменьшилось до 37 и 36 (hit + read). Размер страницы PostgreSQL — 8 KiB; счётчики отражают обращения к буферам, а не только чтение с диска.

Низкоселективный предикат `order_status = 'delivered'` возвращает 96 478 строк, около 97 % таблицы. При наличии составного индекса планировщик самостоятельно выбрал `Seq Scan`: чтение почти всей таблицы через индекс потребовало бы лишних обращений к страницам. Параметры принудительного выбора scan не менялись.

Время отражает один запуск с текущим состоянием кэша и может меняться. Для данного запроса основной эффект индекса — сокращение проверяемых записей и обращений к буферам. Частичный индекс значительно меньше полного и подходит нагрузке по недоставленным заказам. Оба тестовых индекса удалены в конце SQL; команды создания оставлены также в комментариях по требованию задания.

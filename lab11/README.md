## Представления и аналитический запрос

`lab.v_order_summary` возвращает по одной строке для каждого заказа: штат покупателя, число позиций, сумму `price + freight_value` и дату покупки. Предварительная агрегация позиций исключает размножение строк заказа. `LEFT JOIN` сохраняет заказы без позиций, подставляя нулевые число позиций и сумму.

`lab.mv_monthly_state_sales` физически хранит месячные итоги по штатам: число заказов и сумму позиций с доставкой. Это сумма стоимости всех позиций, а не подтверждённых платежей или только доставленных заказов. Команда `REFRESH MATERIALIZED VIEW lab.mv_monthly_state_sales` обновляет снимок.

Аналитика использует четыре CTE: `monthly` берёт месячные итоги, `with_previous` добавляет сумму предыдущего доступного месяца, `growth` рассчитывает изменение в процентах, `ranked` ранжирует штаты внутри месяца. Итог выводится по CE; при нулевой предыдущей сумме изменение равно NULL.

## Иерархия

```text
BR (Brazil)
└── ST:CE (CE)
    ├── CT:CE:fortaleza (fortaleza)
    └── другие города из двадцатки по числу клиентов
```

Такая ветвь создаётся для каждого реального штата. Города отбираются через `ROW_NUMBER()`, при равном числе клиентов — по названию. Идентификатор включает штат, поэтому одинаковые названия городов разных штатов не смешиваются.

Базовая часть прямой рекурсии выбирает `ST:CE` с `depth = 0` и путём `{ST:CE}`. Рекурсивная часть присоединяет дочерние узлы по `parent_id`, увеличивает глубину и дописывает идентификатор к массиву `path`. Пример пути: `{ST:CE,CT:CE:fortaleza}`. Рекурсия завершается, когда очередная итерация не находит детей; условие проверки массива пути дополнительно запрещает повторный проход того же узла.

В обратном запросе база — город `CT:CE:fortaleza`, рекурсивная часть находит родителя по `parent_id`. Цепочка: `CT:CE:fortaleza`, `ST:CE`, `BR`. В последнем запросе база содержит каждый штат, а потомки считаются по строкам с положительной глубиной; сам штат в счётчик не включается.
